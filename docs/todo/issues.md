## 상세

### I-1 LocalStack 재시작 때 `init-aws.sh`가 중간에 멈춤 (열림)
- 증상: 11-13 19:26 LocalStack 재시작 뒤 버킷 `gyeol-local-uploads`·`covers`, 큐 `guess-dlq`·`artist-image-dlq`가 없었다.
- 원인: 이미 있는 큐를 다른 VisibilityTimeout으로 다시 만들려 해서 `QueueAlreadyExists`가 나고 스크립트가 멈춤(갈래 1 확인).
- 우회: 갈래 1이 `covers` 버킷과 `gift-image` 큐를 손으로 만들었고, 이후 새 큐(`code-match`)도 손으로 만듦.
- 남은 일: 스크립트가 이미 있는 자원을 건너뛰게(멱등) 고치기. Takeout 업로드 확인 전에 필요. 웹 9단계 뒤 처리 예정.

### I-2 worker 통합 테스트가 함께 돌릴 때 SQS 404 (열림)
- 증상: ⑥ 구현 중 api·worker 테스트를 한 번에 돌리자 `RoomSongIntegrationTest`가 시작 단계에서 SQS 404. 다시 돌리니 통과.
- 추정 원인: 테스트 컨테이너(LocalStack)가 뜨는 타이밍. 확정 아님.
- 남은 일: 다시 나오면 큐 생성 대기 조건을 확인한다. 지금은 기록만.

### I-3 방 숨김 시각 시계 불일치 (닫힘)
- 증상: "숨긴 뒤 7일" 테스트가 6일로 계산되어 실패.
- 원인: `hidden_at`은 DB `now()`, `purge_at`은 앱 시각이라 몇 ms 어긋남.
- 해결: `RoomRepository.hide`가 두 값을 같은 앱 시각으로 넣음. 커밋 `7d3824b`.

### I-4 구현 기록 절 번호 충돌 (닫힘)

### I-6 인증 코드 만료 시각 없음 (닫힘)
- 증상: 방 만들기·다시 받기 응답의 `expiresAt`은 초안 만료(1시간)라 코드 만료(10분)를 웹이 추정.
- 해결: 응답에 `codeExpiresAt` 추가. 커밋 `4552764`. 웹은 3단계에서 이 필드로 교체.

### I-7 방장 암호 재설정 API 없음 (닫힘)
- 해결: 갈래 1이 `HostResetController` 구현, 커밋 `2099a96`(api 47 통과). 설계와 다르게 정한 점: 없는·숨긴 방은 404(공개 요약 API로 이미 알 수 있어 숨길 정보 아님), 메일 제한은 기존 규칙 "1시간"(같은 이메일 5통·IP 20통), IP 분당 제한은 참가와 같은 값, 보내기 202·확인 200. 관리 세션이 추천안으로 수용.
- 이전 기록:
- 증상: 설계(`room-api-db.md` 3절)에는 `POST /rooms/{rid}/host-reset`·`/verify`가 있으나 메일 문구(`MailTemplates.HOST_RESET`)와 DB purpose 값만 있고 엔드포인트가 없음. 웹 6-d를 만들 수 없음.
- 결정(추천안으로 진행): 갈래 1이 설계대로 구현(코드 메일, 5회 실패 잠금, 방장 이메일은 화면에 안 보임, 응답에 `codeExpiresAt`). 완성되면 관리 세션이 커밋하고 A가 6-d를 만든다. A는 그동안 5단계의 나머지 화면을 먼저 한다.

### I-10 방장 암호 재설정 뒤 다른 기기 열쇠 유지 (열림, 사용자 결정 대기)
- 현재: 재설정해도 방장의 다른 기기 열쇠는 그대로(참가자 새 암호 발급과 같은 규칙).
- 위험: 누군가 방장 이메일을 빼앗아 재설정하면, 진짜 방장의 기기도 계속 들어올 수 있지만 반대로 공격자를 내보낼 수단이 없음(공격자 기기 열쇠도 유지).
- 선택: (가) 지금대로 유지 — 방장의 다른 기기가 로그아웃되지 않음 / (나) 재설정 때 다른 기기 열쇠 모두 폐기 — 안전하지만 방장 기기가 모두 다시 들어와야 함.
- 추천: (나). 재설정은 "암호를 잊었거나 의심될 때" 하는 일이라 다른 기기를 정리하는 쪽이 보통의 기대와 맞음. 다만 기존 동작 규칙(setPin과 같은 규칙)을 바꾸는 일이라 자동 진행하지 않고 사용자 결정으로 남김.
