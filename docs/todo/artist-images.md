# 가수 이미지

상태: 구현 (2026-11-10), V18 `artist_image`, worker 역할 `artist`, 큐 `artist-image`

많이 들은 가수 순위에 가수 이미지를 보여 준다. 지금은 첫 글자 타일만 나온다 (Cover Art Archive는 음반 표지만 있다).

## 찾는 순서

1. **Wikimedia Commons 사진** — MusicBrainz 가수의 Wikidata 연결 → Wikidata 대표 이미지(P18) → Commons 파일. S3에 저장하고 저작자·라이선스를 함께 저장한다.
2. **YouTube Topic 채널 프로필 이미지** — 1이 없을 때. 그 가수 Topic 영상 → 채널 → 프로필 이미지 주소. S3에 복사하지 않고 주소만 30일까지 보관, 지나면 새로 조회한다.
3. **대표 앨범 표지** — 그 가수의 곡 중 사용자가 가장 많이 들은 곡의 저장된 표지.
4. **글자 타일** — 위가 모두 없을 때.

## 사전 조사 (실제 Takeout, 2026-11-10)

| 항목 | 결과 |
|---|---|
| 상위 10명 Commons 사진 | 10명 |
| 상위 50명 Commons 사진 | 44명 (88%), 라이선스는 모두 CC BY 또는 CC BY-SA 2.0~4.0 |
| Commons 사진 없는 6명의 YouTube 프로필 | 6명 모두 있음 → 상위 50명 전원 이미지 |

사진의 내용(인물인지 로고인지, 촬영 시기)은 눈으로 확인하지 않았다.

## 지켜야 할 조건

| 출처 | 조건 |
|---|---|
| Commons (CC BY / BY-SA) | 사진마다 저작자·라이선스 표시. 화면에서는 마우스를 올리면 보이고, 순위 아래에 출처 한 줄 |
| YouTube API | YouTube가 출처임을 표시, YouTube 이용약관 링크, API 데이터는 30일 안에 삭제 또는 갱신, 이미지 복사 저장 안 함 |

YouTube 프로필을 가수 사진 용도로 쓰는 것은 정책에 명시되어 있지 않다 (조건을 지키면 위험은 낮다고 판단, 법률 검토는 아님). 문제가 되면 2단계를 빼고 3단계로 넘긴다.

## 구현 범위

| 위치 | 변경 |
|---|---|
| DB | `artist_image` (가수, 출처, S3 키 또는 주소, 저작자, 라이선스, 확인 시각) |
| external-fetcher | Wikidata·Commons 조회, YouTube 채널 이미지 조회 (외부 호출은 fetcher에서만) |
| worker | 가수 이미지 큐: 순위에 나오는 가수만, 가수당 한 번 (전역 캐시), YouTube 주소는 30일 뒤 갱신 |
| api | 가수 순위에 이미지·출처 포함, Commons 이미지 전달(표지와 같은 방식) |
| web | 가수 타일 자리에 이미지, 출처 표시 |

추가 호출은 가수당 MusicBrainz 1번, Wikidata·Commons 2번, YouTube API 몇 건 수준이다.

## 구현 후 확인 (실제 Takeout 세션, 2026-11-10)

| 항목 | 결과 |
|---|---|
| 처리 대상 (식별된 곡 기준 상위 50명) | Commons 44명, YouTube 6명, 오류 0, 약 1분 43초 |
| 화면 순위 상위 50명 | Commons 35 · YouTube 4 · 대표 앨범 표지 1 · 글자 타일 8 |
| 글자 타일 8명 | 모두 Topic 채널로만 들은 가수(MusicBrainz 가수 없음, `artistId` 없음) |

처음 시험에서는 Commons 썸네일 주소가 `thumb.wikimedia.org`로 와서 허용 목록(`upload.wikimedia.org`)에 걸려 전부 "없음"으로 저장됐다. 두 호스트를 허용하고, 요청이 거절되면 경고 로그를 남기게 고쳤다.

사진 표시 (2026-11-10 추가):

- 세로로 긴 사진은 위쪽(얼굴)을 남기고 자른다 (YOUNHA 전신 사진이 옷만 보이던 문제).
- 가로가 세로의 2배 이상인 사진은 자르지 않고 전체를 넣는다 (Buzz 5명 가로 사진). 16:9 단체 사진은 가운데를 잘라도 대부분 보여 자른다.
- Commons 썸네일은 짧은 쪽이 250px가 되게 받는다 (가로로 긴 사진이 흐려지지 않게, 너비 상한 1000px).
- 이미지 주소에 확인 시각을 붙여, 다시 받은 사진이 브라우저 캐시에 막히지 않게 한다.
- YouTube 기본 프로필(채널 이름 첫 글자 그림)은 없음으로 보고 대표 앨범 표지로 넘긴다 (Brown Eyes, Release). 처음에는 주소의 `/ytc/`로 골랐는데 ZARD 공식 로고도 `/ytc/` 주소라 버렸다. 지금은 fetcher가 이미지를 받아 내용으로 판별한다: 흰색·검은색이 아닌 단색 바탕이 80% 이상이고 두 번째 색이 흰색이면 기본 프로필. 실제 프로필 23장 중 기본 2장만 걸렀다 (흰 바탕 글자 로고·손그림·검은 바탕 로고는 통과).
- 직접 지정 (V20 `artist_image_rule`): 자동 선택이 맞지 않는 가수만. ZARD는 Commons 관련 사진이 2007년 추모 공간 사진 4장뿐이라 Commons를 건너뛰고 YouTube 공식 로고를 쓴다.
- 사진 고르기는 그대로 Wikidata 대표 사진(P18) 한 장이다. 대표 사진이 인물이 아닌 경우는 직접 지정으로 넘긴다.

Topic 채널로만 들은 가수 (2026-11-10 추가, V19 `channel_image`):

- 곡이 식별 대상 밖이라 가수 기록이 없는 Topic 채널 가수는 채널 이름 기준으로 따로 찾는다. 가수 기록은 만들지 않는다.
- 순서: 채널 이름으로 MusicBrainz 가수 검색 (이름·별칭이 정확히 같고, 표기와 가장 많이 맞는 가수) → Commons 사진 → 그 Topic 채널의 YouTube 프로필 → 없음.
- 같은 이름 가수가 여럿이면 그 채널에서 많이 들은 곡(최대 3곡)이 녹음 목록에 있는 후보가 하나뿐일 때만 연결한다. 검색 점수 차(10점)로 고르던 규칙은 RAINBOW를 영국 록 밴드로 잘못 연결해서 버렸다.
- 실제 세션 Topic 채널 50곳: 하나뿐일 때만 연결 → Commons 23 · YouTube 22 · 없음 5, 들은 곡 확인 추가 → Commons 34 · YouTube 15 · 없음 1 (새로 연결된 11곳은 모두 한국 가수로 맞게 연결됨을 확인, 처리 약 5분). 화면 상위 50명 중 글자 타일이던 10명 → 8명 채움 (Commons: 버스커버스커·AKMU·god·Apink, YouTube: Red Velvet·1TYM·QWER·김동률).
- 남은 1명: Release (같은 이름 가수 없음, YouTube 기본 프로필).
