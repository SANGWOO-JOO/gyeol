# 음악 방 기획 (2026-11-11)

상태: 기획 확정, 프로토타입 작성 중, 구현 전. API·DB 설계는 `room-api-db.md`(11-13 승인). 구현 순서: ⓪ 측정·P0 → ① 방·참가·담기 → ② 지도 데이터 → ③ 메일 → ④ 선물 → ⑤ 놀이터 → ⑥ 관리자.
프로토타입: Claude Design 캔버스 "결 프로토타입" (비공개 링크, 작성자만 열람).

## 1. 왜 바꾸나

- 지금 곡 고르기는 "곡 3~5개 → 추천 20곡"이다. 결과까지 약 6분 걸렸다 (11-11 1회, LLM_MODE=fake, 후보 50곡 보강이 대부분).
- 추천 20곡은 비교 대상(스트리밍 앱 추천)이 강하고, 공유할 이유가 약하다.
- 최근 흐름은 "취향 유형 + 친구와 비교"다. Spotify Blend(일치도와 이어 주는 곡), Wrapped 2025 Party·Clubs·Listening Age, YouTube Recap 성격 유형(2025 첫 출시), Airbuds 궁합 점수, Whohears(YouTube 재생목록 일치도).
- 대부분은 계정을 연동해야 쓸 수 있다. 결은 가입 없이 곡 몇 개로 할 수 있고, 근거가 붙은 설명을 줄 수 있다.

## 2. 개념: 링크 하나 = 함께 만드는 음악 방

| 인원 | 결과 |
|---|---|
| 1명 | 내 취향 DNA (요약, 장르·연대·분위기 구성, 근거 붙은 설명) |
| 2명 | 궁합 점수, 겹치는 결·다른 결, 둘을 이어 주는 곡 |
| 3명 이상 | 함께 듣기 추천 리스트 (곡마다 누구 취향에서 왔는지 표시) |

- 사람마다 곡을 검색해 3~5개 넣는다 (지금 곡 고르기 검색 재사용).
- 지식(근거 조각·곡 설명·곡 벡터)은 공용, 취향(고른 곡·취향 벡터)은 참가자별.
- DNA와 궁합은 고른 곡만 보강하면 되므로 후보 50곡 보강이 없다. 추천은 "더 받기"로 분리.

## 3. 참가와 인증

### 방장
- 방 만들 때 닉네임, 4자리 암호, **이메일 인증 필수** (A안, 11-11 결정).
- 인증은 메일로 6자리 코드를 보내고 화면에 입력하는 방식. 링크 클릭 방식은 카톡 안 브라우저와 메일 앱 브라우저가 달라 흐름이 끊겨서 쓰지 않는다.
- 코드: 10분 유효, 5번 틀리면 다시 받기, 다시 받기는 1분에 한 번.

### 참가자
- 방 링크 → 닉네임 + 4자리 암호. 이메일·가입 없음.
- 방 안 닉네임 중복 금지, 닉네임 12자 이하.
- 방 최대 **5명**(11-11 변경, 지도 궤도 수 때문), 곡 수 제한 없음(11-11 변경, 10절). 방장은 참가자 빼기·참가 마감 가능.

### 다시 들어오기
- 같은 브라우저: 참가할 때 받은 열쇠(무작위 토큰)를 localStorage와 HttpOnly 쿠키에 저장해 자동 인식.
- 다른 브라우저·기기: [나는 OO예요] + 4자리 암호.
- 열쇠가 사라지는 경우: 시크릿 창, 사이트 데이터 삭제, iPhone Safari의 장기 미사용 정리, 카톡 안 브라우저와 다른 브라우저 사이 이동.

### 보안 최소선
- 암호는 BCrypt 해시로만 저장, 원문은 저장·로그 출력 금지 (4자리는 다른 서비스 비밀번호를 재사용하기 쉬움).
- 참가자별 5번 틀리면 10분 잠금, IP별 요청 제한.
- 피해 범위: 그 방에서 그 사람의 곡 수정. 지도·노래는 참가한 사람만 본다(11-13 변경: 링크만 받은 사람은 초대 화면의 방 이름·사람 수·닉네임만).

### 암호 분실
| 대상 | 방법 |
|---|---|
| 참가자 | 방장이 [새 암호] → 서버가 랜덤 4자리 숫자를 만들어 그 참가자의 암호로 바로 바꿈 → 방장이 카톡 등으로 전달 → 참가자는 그 숫자로 들어옴(별도 코드·만료 없음, 11-11). 틀린 횟수·잠금도 풀림. 기존 기기 열쇠는 유지. 참가자가 직접 암호를 바꾸는 기능은 첫 배포에 넣지 않음 |
| 방장 | 등록 이메일로 재설정 코드 → 새 암호 |

- 암호만 지우는 방식은 지운 뒤 아무나 그 자리를 가져갈 수 있어 쓰지 않는다.

## 4. 개인정보

- 방장 이메일만 저장 (메일을 보내야 해서 원문). 수집 목적("방 복구용") 안내와 동의.
- 방은 영구 보관(11-11 변경, 10절). 방이 삭제될 때 이메일도 함께 삭제. 동의 문구는 "방을 삭제할 때까지 보관"으로.
- 방장이 우주를 삭제하면 바로 숨기고 7일 뒤 이메일·노래·캐릭터 이미지까지 완전 삭제(11-13). 7일 안에는 관리자만 되살림. 안내에 "삭제 후 7일 안에 완전히 지워져요".
- 참가자는 닉네임과 곡만.
- 이메일별·IP별 발송 제한, 가입 여부를 화면에 드러내지 않는다.

## 8. 음악 지도 (11-11 추가)

방은 "친구들과 함께 채우는 음악 지도"가 된다. 비슷한 가수끼리 가까이 놓인 지도에 각자 담은 노래가 가수 원 둘레의 점으로 쌓인다. 참고한 형식은 everynoise.com 장르 지도이며, 그쪽은 음향 특성으로 배치했고 결은 근거 자료 기반 설명(RAG)으로 배치한다.

### 지도 요소
| 요소 | 의미 |
|---|---|
| 가수 원 | 위치는 비슷한 가수끼리 가깝게, 크기는 방 안에서 담긴 노래 수 |
| 노래 점 | 가수 원 둘레, 색은 담은 사람 |
| 구역 이름 | 가까운 가수 묶음에 LLM이 붙인 이름 (근거 포함) |
| 겹친 구역 | 여러 사람 점이 함께 있는 곳 = 궁합 |
| 사이 가수 | 두 사람 구역 사이 가수 = 함께 들을 만한 추천 |

결과 화면을 따로 두지 않고 지도 자체가 결과다 (혼자: 내 구역, 둘: 겹친 구역·사이 가수, 여럿: 모두의 지도).

### 만드는 순서
1. 가수 근거 조각 모으기 (MusicBrainz·Last.fm, 지금 enrich 재사용)
2. 가수 설명 쓰기 (RAG, 지금은 곡 단위만 있음 → 가수 단위로 확장)
3. 설명 → e5 384차원 벡터
4. 2차원 좌표: UMAP (Python 임베딩 서비스에 추가)
5. 구역 이름: 묶음마다 LLM, 근거와 함께
6. 이웃 찾기: pgvector + Last.fm 비슷한 가수로 보정

### 결정
| # | 항목 | 결정 |
|---|---|---|
| ① | 지도 범위 | 모두 같이 쓰는 큰 지도 하나, 방은 참가자 구역을 확대해 보여 줌 (좌표 고정) |
| ② | 초기 데이터 | **한국·일본·미국 인기 가수, 나라별 500명 (약 1,500명)** |
| ③ | 새 가수 | 가까운 이웃 좌표 평균 자리에 배치, 전체 재계산은 가끔 |
| ④ | 반영 방식 | 처음엔 몇 초마다 새로고침, 나중에 실시간(SSE/WebSocket) |
| - | 다른 사람 노래 공개 | 담는 즉시 지도에 보임 (지도에 점이 쌓이는 게 핵심이라 6절 화면 권한 논의의 ①을 이렇게 정리) |

### 초기 데이터 채우기 (②)
- 목록: Last.fm `geo.getTopArtists` (South Korea / Japan / United States), 나라별 상위 500
- 거르기: Last.fm 나라별 순위는 그 나라 사용자가 많이 듣는 가수라 해외 가수가 섞인다. MusicBrainz 출신 국가(KR/JP/US)로 나라를 다시 정한다. 세 나라 밖 가수는 제외
- 예상: MusicBrainz 초당 1회 제한으로 약 2~3시간, Bedrock Haiku 4.5 설명 비용 약 3~5달러 (가수당 입력 약 1,500·출력 약 200 토큰 가정)
- 비용·단가는 실행 전에 실제 토큰 수로 다시 계산하고 확인받는다

### 배치 검증 결과 (11-11, 로컬, 1회)
데이터: Last.fm 나라별 순위 → MusicBrainz 출신 국가로 거른 한·일·미 157명 (각 52~53명), fetcher 근거 조각(MusicBrainz·Wikipedia·Last.fm). 임베딩 e5-small 384차원, 2D는 UMAP(n_neighbors 10). 결과 파일은 DB에 넣지 않고 작업 폴더에만 둠.

평가 기준: Last.fm "비슷한 가수" 중 목록 안에 있는 쌍이 지도에서 서로 이웃(10명) 안에 드는 비율, 그리고 이웃 중 같은 나라 비율.

| 가수 글 | 157명 Last.fm 일치 (무작위 6%) | 2D 이웃 5명 같은 나라 |
|---|---|---|
| 근거 조각 원문 | 32% | 95% |
| 나라·도시 단어 제거 | 34% | 85% |
| + K-/J- 장르 접두어 제거 | 32% | 82% |

- 384차원과 UMAP 2D의 일치율이 거의 같아 UMAP이 이웃 관계를 잘 지킨다.
- 잘 묶임: 걸그룹(aespa·NewJeans·BLACKPINK), 한국 인디(혁오·잔나비·검정치마·wave to earth), J-pop(米津玄師·宇多田ヒカル·藤井 風)
- 문제: 나라로 강하게 뭉침. 가수 이름의 문자(한글·가나)와 근거 글의 언어 자체가 나라 신호가 되는 것으로 보임(추정). 미국 쪽은 장르보다 나라로 묶임(Slipknot 옆에 Big Thief)

Bedrock 설명 비교 (나라별 10명 = 30명, Haiku 4.5, 근거만 사용·나라 언급 금지 프롬프트, 실제 토큰 입력 29,649·출력 6,653, 약 0.06달러 추정):

| 30명 안에서 | Last.fm 일치 (이웃 5명, 무작위 17%) | 이웃 3명 같은 나라 |
|---|---|---|
| 원문 조각 (나라 단어 제거) | 74% | 66% |
| Bedrock 설명만 | 56% | 51% |
| 섞기 (설명 0.3 + 원문 0.7) | **88%** | 71% |
| 섞기 (설명 0.5 + 원문 0.5) | 79% | 69% |

- 설명만 쓰면 나라 쏠림은 줄지만(51%) Last.fm 일치도 떨어진다. Last.fm 유사 가수 자체가 같은 나라에 치우쳐 있어 일부는 기준의 편향.
- 설명은 엉뚱한 이웃을 줄인다 (원문: Lil Baby→Evanescence, NIN→TWICE / 설명: Lil Baby→Gunna, Evanescence→Soundgarden)
- 표본이 30명·34쌍이라 가중치는 확정하지 않는다. 현재 후보: 두 벡터 섞기(설명 0.3~0.5)

157명 전원 설명 생성 후 (추가 127명 토큰 입력 91,606·출력 24,787, 30명 포함 합계 약 0.28달러 추정):

| 설명 가중치 | Last.fm 일치 384차원 / 2D (무작위 6%) | 2D 이웃 5명 같은 나라 |
|---|---|---|
| 0.0 (원문만) | 32% / 33% | 86% |
| 0.3 | 40% / **42%** | 83% |
| **0.5** | **43%** / 41% | **76%** |
| 0.7 | 42% / 38% | 70% |
| 1.0 (설명만) | 37% / 33% | 64% |

- 섞으면 원문만보다 이웃 품질이 약 10%p 오르고 나라 쏠림도 줄어든다. 설명만 쓰면 둘 다 나빠진다 → 근거 원문과 RAG 설명을 섞는 것이 가장 낫다.
- **결정: 가수 벡터 = 원문 조각 벡터 0.5 + RAG 설명 벡터 0.5** (157명 1회 측정, 표본이 커지면 다시 확인)
- 0.5 이웃 예시: NewJeans→BABYMONSTER·ITZY·BLACKPINK, 혁오→Redoor·잔나비·AKMU, 잔나비→…·Saucy Dog(JP), ELLEGARDEN→ASIAN KUNG-FU GENERATION·blink-182(US), Lil Baby→Megan Thee Stallion·21 Savage, Evanescence→Soundgarden·Alice in Chains
- 남은 문제: 일부 엉뚱한 이웃(Nine Inch Nails→B'z·くるり, Halsey→볼빨간사춘기). 근거 조각이 적은 가수에서 생기는 것으로 보임(추정). Last.fm 비슷한 가수로 위치를 당겨 주는 보정을 구현 때 시험

### 지도 판 1: 나라별 100명 = 300명 (11-13, 로컬, 1회)
파이프라인 구현 후 첫 실행(`room-api-db.md` 8절). Last.fm 나라 이름은 한국만 "Korea, Republic of"여야 결과가 나온다("South Korea"는 빈 목록).

| | 11-11 시험 (157명) | 판 1 (300명) |
|---|---|---|
| Last.fm 비슷한 가수 쌍이 이웃 10명 안 (384차원 / 2D) | 43% / 41% (무작위 6%) | 33% / 33% (무작위 3%, 쌍 1,868개) |

| ⑭ | 참가자 암호 초기화 (11-11) | 방장이 [새 암호]를 누르면 서버가 랜덤 4자리를 만들어 그 참가자의 암호로 바로 바꾸고, 방장이 직접 전달한다. 코드 입력 단계·만료 없음. 참가자가 스스로 암호를 바꾸는 화면은 만들지 않는다(A안). 저장은 BCrypt, 5회 실패 10분 잠금 유지 |
| ⑮ | 내 정보 (11-11) | 참가자 판에서 내 줄을 누르면 "내 정보" 판(6-h). **닉네임 바꾸기**(12자, 방 안 중복 금지, 친구 화면에 바로 반영, "나는 OO예요" 버튼도 새 이름)와 **이 기기에서 나가기**(이 기기 열쇠만 지움, 노래 유지)만 둔다. 우주 나가기는 보류(방장 내보내기로 대신), 내 암호 바꾸기는 ⑭대로 없음 |
| ⑯ | 50곡 선물 캐릭터 (11-11, **첫 배포 포함**, 기준 10곡→50곡 변경) | 한 우주에서 내 노래가 50곡 단위(50·100·150…)에 처음 닿을 때마다 선물 상자(4-j) → 담은 노래의 장르 비율·분위기로 Haiku가 프롬프트를 쓰고 Bedrock 이미지 모델이 캐릭터 생성 → S3 저장 → [이 캐릭터로 바꾸기]/[그대로](4-k). 바꾸면 얼굴 원·참가자 판에 쓰고, 지도 위성은 사람 색 유지. 받은 캐릭터는 내 정보(6-h)에 모여 다시 고를 수 있음. 노래를 빼서 50곡 아래로 내려가도 받은 캐릭터는 유지. **최고 기록 기준**: 빼고 다시 담아 같은 단계를 또 넘으면 상자 없음(반복 수령 방지). **한도(11-11 변경)**: 상자는 사람·우주당 **하루 1개**. 하루에 50곡 단계를 여러 번 넘으면(노래 하루 100곡 한도라 최대 2단계) 첫 상자만 그날 열고 나머지는 "기다리는 상자"로 쌓여 다음 날부터 하루 1개씩 열림(사라지지 않음). 노래 담기는 사람·우주당 하루 100곡(11-11 유지 확정: 비용 절감보다 MusicBrainz·Last.fm 요청 제한 보호, 새 아티스트 분석 대기열 보호, 지도 가독성 보호가 목적). 비용은 사람당 하루 최대 1장(Style Guide 기준 약 98원), 우주당 하루 최대 5장. 프롬프트에 실제 가수 이름·얼굴 금지(사람 얼굴·기존 캐릭터를 닮지 않게, 결 고유 화풍을 고정한 귀여운 캐릭터만: 둥근 몸·파스텔·평면, 장르·분위기는 색·소품·표정으로). 생성 실패나 서비스 전체 하루 예산 초과 시 미리 만든 기본 캐릭터로 대체(예산 값은 구현 때 정함). 이미지 모델·리전은 11-11 확인 결과 아래 "⑯ 이미지 모델 확인" 참고 **남은 곡 표시(11-11)**: 남은 곡 = 다음 50곡 단위(최고 기록 기준) − 지금 곡 수, 노래를 빼면 50을 넘을 수 있고 실제 숫자를 그대로 보여 줌. 상태 3가지 — ① 오늘 아직 안 받음: "선물까지 N곡"(아래 바·담은 직후 알림은 3곡 이하일 때만), ② 오늘 받았고 다음 단계 전: "오늘 선물은 받았어요 · +N곡", ③ 오늘 받았고 다음 단계도 넘음: "기다리는 상자 K개 · 내일 열려요". 다음 날 첫 입장 때 기다리는 상자가 있으면 상자 열기(4-j)를 바로 띄움. 표시 위치: 아래 바, 담은 직후 알림(4-e), 내 정보(6-h), 정리 보드 4-l |
| ⑰ | 방 아래 탭 바 + 놀이터 (11-11) | 휴대폰 방 화면 아래에 탭 4개: **지도 · 놀이터 · 검색 · 내 노래**(지니 하단 탭 참고). 놀이터는 우주에 모인 노래로 노는 체험 모음. **첫 배포는 "코드 맞추기" 하나만**(11-12 이름 확정: "우리 코드가 맞네" + 음악 코드 말장난, 동성·이성 모두 자연스러움. 결과 문구 "상우 × 민지, 코드가 87% 맞아요". 각자 노래 5곡부터 열림(기본값)): 같은 우주 두 사람을 골라 지도 위 거리·겹친 아티스트·노래·장르 비율로 점수를 계산하고, LLM은 근거(RAG 설명) 기반 이유만 씀. 취향 월드컵은 다음 후보, AI 토론 배틀은 그 확장. MBTI·연애관·심리 분석·인생 OST는 근거 없는 생성이라 제외, 비슷한 사람 찾기는 우주 비공개 원칙과 충돌해 제외. 11-12 탭 바를 방 화면 전체에 적용: 떠 있던 "내 노래" 바는 없앰(앨범 표지·곡 수는 내 노래 탭으로), 아래에서 올라오는 판은 탭 바 위에 얹음, 노래가 뜬 알림은 탭 바 바로 위. 선물 표시는 내 노래 탭 맨 위 줄(늘 보임) + 탭 금색 배지(선물까지 3곡 이하면 남은 곡 수, 기다리는 상자가 있으면 "상자"), 오늘 이미 받았으면 배지 없음. 행성 자세히(4′)는 탭 바를 덮는 판이라 탭 바 없음. PC는 지도가 늘 왼쪽에 보여서 오른쪽 판 탭을 **놀이터 · 검색 · 내 노래 · 참가자**로 맞추고(아티스트 자세히는 행성을 눌렀을 때만 판에 뜸), 선물 배지는 "내 노래" 탭 옆. 모바일 보드마다 1:1 PC 보드를 둠(11-12, 번호 뒤 -PC): 입력 화면은 가운데 카드, 방 상태는 지도+판(알림은 지도 아래 가운데), 방 안에서 여는 설정·관리·선물은 방 위 대화상자, 내 정보는 오른쪽 판 |
| ⑥ | 방장 이메일 인증 순서 | 지금처럼: 방 만들기 → 메일 코드 → 방 생성 |

화면 구성: 지도는 화면 전체, 머리(로고·방 이름·얼굴·초대)는 지도 위에 뜸, 아래는 내 위성 5칸 + 검색 버튼의 떠 있는 바. 휴대폰은 아래에서 올라오는 판, PC는 오른쪽 옆 판. 범례·확대축소 버튼 없음(손가락 확대, "우리 구역으로" 버튼만).

## 10. 곡 수·보관·관리자 (11-11)

### 곡 수: 제한 없음
- 1인·방 전체 모두 곡 수 제한 없음. "친구끼리 함께 쌓아 가는 노래 은하"
- 친구와 결 맞추기(궁합 표시)는 3곡부터
- 아래 바는 칸 5개 대신 최근 표지 몇 장 겹침 + "내 위성 N개", 누르면 전체 목록(무한 스크롤, 최근·은하별 정렬)
- 뒤에서 지키는 장치(사용자에게 보이지 않음): 새 행성 준비는 1인 동시 3개까지 줄 세움, 담기 1분 30회 제한, 지도는 줌 단계별 표시(멀리서는 은하를 구름 + 개수로 묶음)와 보이는 범위만 조회

### 보관: 영구
- 방은 방장이 지우거나 관리자가 지울 때까지 남는다 (30일 자동 삭제 없음)
- 방장 이메일 보관 기간 = 방이 남아 있는 동안. 삭제 요청 연락처를 안내에 한 줄

### 관리자 페이지 (첫 배포에 넣음)
| 기능 | 내용 |
|---|---|
| 로그인 | 슈퍼어드민 전용, 비밀번호(BCrypt) + 2단계 인증(TOTP), 5회 실패 잠금, 세션 1시간·HttpOnly |
| 방 목록 | 이름, 방장 닉네임, 참가자 수, 곡 수, 만든 날, 마지막 활동일, 검색·정렬 |
| 방 상세 | 참가자, 담긴 노래, 방장 이메일(일부 가림) |
| 방 삭제 | 숨김(소프트 삭제) → 7일 뒤 완전 삭제, 되살리기 가능 |
| 이름 정리 | 부적절한 방 이름·닉네임 변경, 참가자 내보내기 |
| 감사 기록 | 누가·언제·무엇을 했는지 |

- 슈퍼어드민 계정: 테이블 구조만 Flyway에 두고, 계정은 운영 DB에 직접 INSERT (로컬에서 BCrypt 해시 생성). 비밀번호·해시는 저장소(공개)에 절대 넣지 않는다. 절차만 문서화
- 접근 제한: 단일 서버(k3s)는 **인그레스(Traefik) IP 허용 설정으로 /admin 경로만 지정 IP 허용** + 로그인 + 2단계 인증. 비용 0원. IP가 바뀌면 Helm 값 수정 후 배포
- WAF: EC2에는 직접 못 붙고 ALB(월 약 16달러~)나 CloudFront가 필요해 운영에는 쓰지 않음. **EKS 단계(6단계)에서 ALB + WAF IP 규칙으로 시연**하고 내림

### ⑯ 이미지 모델 확인 (11-11)

- `aws bedrock list-foundation-models --by-output-modality IMAGE`로 7개 리전 조회. **서울(ap-northeast-2)·도쿄에는 이미지 생성 모델이 없음.**
- 글로 그림을 만드는 모델은 **us-west-2(오레곤)** 에만 온디맨드로 있음: `stability.stable-image-core-v1:1`, `stability.sd3-5-large-v1:0`, `stability.stable-image-ultra-v1:1`.
- 기준 이미지 화풍을 따라 그리는 `stability.stable-image-style-guide-v1:0`은 us-east-1·us-west-2에서 교차 리전 프로필(`us.` 접두사)로 호출.
- Amazon Nova Canvas는 2026-09-30 EOL, Titan Image Generator는 가격표에만 남고 모델 목록에 없음 → 후보에서 제외.
- 장당 가격(Stability 모델은 AWS Marketplace 과금이라 가격 API에 안 나옴, 공식 숫자 미확인): Core 약 $0.04, SD3.5 Large $0.08, Ultra 약 $0.14, Style Guide $0.07(Bedrock 가격표 요약).
- 서버는 서울이어도 이미지 생성만 us-west-2로 호출. 보내는 것은 프롬프트(장르·분위기)뿐이라 개인정보 이동 없음.
- 실제 호출 전에 콘솔에서 모델 접근(Marketplace 구독) 확인 필요. 아직 호출하지 않음.
